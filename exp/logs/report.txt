note: invalid = 0 is a STRUCTURAL GUARANTEE under H ONLY, and the reason is not that
      its set is filtered — X+'s is filtered too. It is that H's agent SELECTS: it
      returns an index, and an index outside the offered set is not a wrong answer
      but an unrepresentable one. X+'s agent NAMES: it emits a tool name as a
      string, and a string can be any string. Filtering decides what is OFFERED;
      only selection decides what is EXPRESSIBLE.
note: so X+ > 0 in this column is not a bug in the server. It is a weaker model
      calling a tool that `tools/list` did not return — and it scales with
      capability, while H's zero does not. Compare the arms.
note: H wrong-value = 0 is structural too — a declared value is only rendered where
      it is legal, so the value and its legality share one source. X+'s is not: it
      must produce the value itself, and what a model produces can be wrong.
note: J+ vs X is the protocol cell. Same operations, same descriptions, same
      parameters; one is read as text and chosen by index, the other is served by
      a real MCP server and invoked by a native tool call. A gap here would mean
      the comparison is about the protocol; its absence is what licenses reading
      X -> X+ as being about state-dependence.
